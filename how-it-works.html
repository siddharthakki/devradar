How DevRadar Works

An autonomous open-source intelligence pipeline separating genuine architectural momentum from bot-manipulated hype.

🚀 Star Velocity & Momentum Decay

Standard GitHub trending metrics favor established corporate behemoths with 60,000+ legacy stars. DevRadar isolates fast-rising breakout tools using a gravity-decay velocity model:

Score = Stars / (Age_Hours + 2.0)^1.25

This prioritizes projects gaining rapid daily adoption within their first 7 to 30 days while dampening older repositories with dormant maintainer activity.

🛡️ Authenticity & Anti-Bot Index

To combat coordinated star farms, DevRadar computes an authenticity ratio analyzing structural engagement indicators:

  • Fork-to-Star Ratio: Real repositories typically display at least a 3–8% fork ratio. Extreme imbalances (<1.5% with high star bursts) are flagged.
  • Velocity Deviation: Unnatural sudden spikes without organic issue or PR activity trigger score deductions.

⚙️ Hardware & Local-First Profiling

Each repository is inspected for self-hosting and local hardware viability. Readme manifests, configs, and models are categorized into CPU/Minimal, Unified Apple Silicon, or Heavy CUDA (16–24GB+ VRAM) requirements before you clone.

🔄 Autonomous Pipeline Architecture

DevRadar operates 100% serverlessly. A GitHub Action executes on an hourly cron schedule, running engine/analyzer.py and updating atomic time-series history in data/repos.json and data/history.json.
